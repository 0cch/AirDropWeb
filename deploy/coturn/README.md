# coturn deployment

This template runs coturn with short-lived HMAC credentials generated by the AirDrop Web signaling server.

## Requirements

- A public DNS record such as `turn.example.com`
- TCP 3478 and 5349 reachable
- UDP 3478 and UDP 49160-49200 reachable
- Valid TLS certificate files:
  - `certs/fullchain.pem`
  - `certs/privkey.pem`

## Start

```bash
cp .env.example .env
openssl rand -hex 32
# Put the generated value in .env as TURN_SECRET
docker compose up -d
docker compose logs -f
```

Configure AirDrop Web with the same secret and public URLs:

```bash
TURN_URLS="turn:turn.example.com:3478?transport=udp,turns:turn.example.com:5349?transport=tcp" \
TURN_SECRET="same-secret-as-coturn" \
TURN_REQUIRED=1 \
./deploy.sh
```

## Firewall

For the default relay range:

```bash
ufw allow 3478/tcp
ufw allow 3478/udp
ufw allow 5349/tcp
ufw allow 49160:49200/udp
```

Only expose the relay range actually configured in `docker-compose.yml`.

## Verify

- `/health` reports `turnConfigured: true`
- `/api/ice-config` includes a TURN server
- The transfer page shows `TURN 加密中继` when direct connectivity is unavailable

Keep `TURN_SECRET` private. It is used to generate expiring TURN credentials and must not be placed in frontend build files.
